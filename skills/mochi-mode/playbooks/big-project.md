# Big project

**When the goal spans weeks, many errands or other people, or fits no other playbook, design the playbook before doing the work.**

1. Frame it. State done as something checkable. Size the scope: tasks, people, money, time. List the blockers and the one-way doors.
2. Design it. Break the work into units that each end in something you can check, riskiest unknown first. Mark which units only the owner can decide, which run in parallel (`swarm`), and which need a contested choice settled (`arena` or `interrogate`). Write the phase list to `data/work/<slug>/plan.md`. Show it to the owner before a multi-day run, and start the reversible early steps meanwhile.
3. Run each unit as an experiment. State what you expect, act, check the result on the real thing, then keep it or undo it.
4. Log each unit as it lands with `show-me-your-work`.
5. Put it on the calendar. Deadlines become events, follow-ups become triggers, and a `project` note points at the work directory.
6. Before handing back, check the whole against the frame, not just the last unit.

**Reply:** the plan you designed, what is done and verified, what is next and when, and what the owner must decide.
