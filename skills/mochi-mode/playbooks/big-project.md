# Big project

**When the goal spans weeks, many errands or other people, or fits no other playbook, design the playbook before you do the work.**

1. Frame it. Write done as a check. Size the scope: tasks, people, money, time. List the blockers and the one-way doors.
2. Design it. Break the work into units that each end in a check, riskiest unknown first. Mark the units only the owner can decide, the units that run in parallel (`swarm`), and the contested choices (`arena` or `interrogate`). Write the phases to `<slug>/plan.md` in the work directory.
3. Before a multi-day run, show the plan to the owner. Start the two-way-door units while you wait.
4. Run each unit as an experiment: state what you expect, act, check the result on the real thing, then keep it or undo it. Log it per `show-me-your-work`.
5. Put deadlines on the calendar and each follow-up in a `schedule_add` with an `at`. Write a line in the memory files that points at the work directory.
6. Before you hand back, check the whole result against the frame from step 1, not only the last unit.

**Reply:** the plan, what is done and verified, what is next and when, and what the owner must decide.
